## 0. What changed, in one paragraph

Before 0c the USB and BLE callers each open-coded the same decision — *offer the line to `mrfw::dispatch()`, else
`parse_command` + `handle_peerkey`/`handle_peername`/`Node::on_command`* — **in opposite orders**, and each rendered
the parser-owned result in its own envelope. 0c adds one function,
`mrfw::exec_console_line(line, len, LineFormat, Print& stream, char* reply, size_t reply_cap)`, in
`src/firmware_commands.cpp`. It makes that decision once, router-first, executes the command once, and renders the
typed result in the caller's chosen envelope. `service_console` and `ble_dispatch_line` each become one call to it
plus their own already-existing refusal envelopes. No verb, handler, context, authority, storage, wire or radio
behaviour is added. `src/fw_main.cpp` shrinks by 43 lines (36 code lines).

## 1. The two live contracts, frozen before editing (0c-0)

### 1.1 Decision graphs at `106c6b8`

**`service_console` (`src/fw_main.cpp:1077-1152`, `#if MR_CONSOLE`)** — intake 1024 B `static char line[]`, `\r`
dropped, overflow marked and refused loudly at `\n`, then, per line:

```
line[pos] = '\0'
  dispatch(line, pos, mrcon) ------------------ true  -> done
  else parse_command(line, pos, cmd)
        ok       -> kind==peerkey  -> char jb[80];  handle_peerkey  -> mrcon.write
                 -> kind==peername -> char jb[256]; handle_peername -> mrcon.write
                 -> else g_node.on_command -> "> " cmdcode_name ctr= depth= [dh=0x][lp=0x][plane=]
                                              + print_reqpubkey_hint
        empty    -> (silence)
        else     -> "peerkey " prefix ? peerkey_err{bad_hex} : "> parse error"
pos = 0
mrcon.service()                                  (once per loop pass, OUTSIDE the drain)
```

**`ble_dispatch_line` (`src/fw_main.cpp:454-604`)** — `len == 0` returns 0 at the top; then **direct handlers**
`whoami`, `version`, `prep-restart`, `rcmd`, `duty`, `limits`, `status`, `cfg set`, `cfg`, `routes`, `peers`,
`peers <x>` (`console_only`), `pull_inbox`, `mark_read`, `del_msg`; then:

```
parse_command(line, len, cmd) ------------------ ok    -> peerkey/peername -> handle_* into out
                                                       -> on_command -> reqpubkey&&queued&&accepted
                                                                        ? write_reqpubkey_sent : write_ack
                                                empty -> 0
   "peerkey "  prefix -> peerkey_err{bad_hex}
   "peername " prefix -> write_peer_name_err{bad_args}
   help family        -> write_err{help, console_only}
   unknown_verb       -> LineSink ls(ble_sink); if (dispatch(line,len,ls)) { ls.flush(); return 0; }
   fallthrough        -> write_err{parse, unknown_cmd|bad_args}
```

⇒ USB asks the **router first**; BLE asks the **parser first**, and never consults the router at all on a
`bad_args` line. That asymmetry is what 0c removes.

## 3. BEFORE/AFTER transcript and side-effect comparison (0c-0, Gate 2)

### 3.1 The instrument, and exactly what it does and does not claim

`tools/probe_inbox_verbs/transcript.py` + `transcript_main.cpp` (both new).

* It **extracts** the two caller regions VERBATIM from a given `src/fw_main.cpp` text by unique-anchor-or-refuse
  (the `ble_guard.py` idiom), writes them into a generated header, and compiles them against the **real**

* ⛔ **It does not compile `src/fw_main.cpp`, and this file never claims it does.** The 0c wiring authority is
  (a) the seam EXECUTED by `probe_main.cpp`'s X rows (§5) and (b) the two adapters PINNED STRUCTURALLY (§6).

* Anchors — serial: everything between `line[pos] = '\0';` and the `pos = 0;` that closes the newline arm; BLE:

## 4. The change itself

### 4.1 `src/firmware_commands.h` — the declaration

```cpp
enum class LineFormat : uint8_t { text, json };

struct LineExec {
    enum class State : uint8_t { unmatched, empty, streamed, buffered };
    State                        state     = State::unmatched;
    size_t                       n         = 0;
    meshroute::console::ParseErr parse_err = meshroute::console::ParseErr::ok;
};
LineExec exec_console_line(const char* line, size_t len, LineFormat fmt, Print& stream,
                           char* reply, size_t reply_cap);
```

No heap, no virtual dispatch, no second command copy, no retained body pointer, no new global, **no new static
RAM buffer** (board RAM +0 on both envs, §9). `State` is a narrow local completion, deliberately **not** the
future `DispatchResult`: no remote authority state exists in it.

### 4.2 What the seam owns, and the one thing it deliberately does not

Owns: (1) the router-versus-parser fork, once, router-first; (2) the typed dispatch of a parsed command to
`handle_peerkey` / `handle_peername` / `Node::on_command`; (3) the transport-selected rendering of that typed
result; (4) the narrow completion.

⛔ **It owns no command-name special case.** The transport-specific NAMED failure envelopes (`peerkey_err`,
`peer_name_err`, the BLE `console_only` help refusal) stay in their transports. That is not a shortcut, it is
**STOP condition 5 read as written** — *"preserving behavior needs command-name special cases in the common seam"*
is a STOP, so a `strncmp(line, "peerkey ", 8)` inside the seam would have been the failure, not the fix. A line
neither surface owns comes back `State::unmatched` **with its `ParseErr`**, and each caller renders its own
established contract — exactly the shape the brief names in 0c-1(4) (*buffered, streamed, completed or
unmatched*). ⓘ This also keeps the tracked inventory's `service_console` and `ble_dispatch_line` surfaces
non-empty and their rows unchanged (§8).

`cmd.kind == CmdKind::peerkey` is the parser's TYPED answer, not a re-test of the line, and the peer-book arms sit
**ahead of** `on_command` on both format arms because `handle_peerkey`/`handle_peername` run `on_command`
themselves — calling it here first would execute the command twice. Both callers already had exactly that shape.

### 4.3 The two adapters

Serial (`src/fw_main.cpp`, inside the unchanged 1024-B intake and its unchanged overflow refusal):

```cpp
line[pos] = '\0';
const mrfw::LineExec ex = mrfw::exec_console_line(line, pos, mrfw::LineFormat::text, mrcon, nullptr, 0);
if (ex.state == mrfw::LineExec::State::unmatched) {
    if (pos >= 8 && !strncmp(line, "peerkey ", 8)) mrcon.println(F("{\"ev\":\"peerkey_err\",...}"));
    else                                           mrcon.println(F("> parse error"));
}
pos = 0;
```

BLE (below the unchanged direct handlers):

```cpp
if (help family) return write_err(out, cap, "help", "console_only");     // MOVED above the seam — see below
LineSink ls(ble_sink);
const mrfw::LineExec ex = mrfw::exec_console_line(line, len, mrfw::LineFormat::json, ls, out, cap);
if (ex.state == …::streamed) { ls.flush(); return 0; }
if (ex.state == …::buffered) return ex.n;
if (ex.state == …::empty)    return 0;
…peerkey_err / peer_name_err / write_err(parse, unknown_cmd|bad_args)…
```

**The one ordering change inside a caller, and why it is neutral by construction.** BLE's help refusal used to sit
*after* the parse; it now sits *before* the seam, because the seam asks the router first and `help` is
router-owned. Every help spelling is a token `parse_command` does not know, so it reached the old refusal as
`unknown_verb` — testing it first therefore refuses the identical set. Proven three ways: the whole help family in
`ble_guard.py`'s 53-line corpus (executed, 212 assertions), the 0c transcript rows (`help`, `help messaging`, `?`,
`helpful`, `HELP` — byte-identical), and X20 (§5), which shows the seam WOULD stream 456 B of index over NUS if
the guard were not there.

**Two consequences measured rather than assumed.**
1. `LineSink ls(ble_sink)` is now constructed once per line that reaches the bottom, where before it was
   constructed only on the `unknown_verb` arm. It is a 1700-B value-initialised stack object; five sibling arms in
   the same function already construct one, so it is the file's own idiom (U3). Board **RAM is +0** on both envs
   and object counts are unchanged (§9); the cost is one 1700-B zero-fill on a parser-owned line, which no output
   or side effect can observe (§3.3).
2. `ls` is flushed **exactly once**, only on the streamed arm — pinned structurally (§6, S23) with two controls
   (§7, X15/X16).

### 4.4 `exec_command()` (UI-7) is untouched

Behaviour-identical, both `firmware_ui.cpp` call sites unchanged, `probe_firmware_ui` at its pin (§10). It is
**not** folded into the seam and the header now says why: `exec_command` runs `Node::on_command` for EVERY kind,
including `peerkey`/`peername`, which the console path deliberately routes to the peer-book handlers (RAM install
+ /mrpeers mirror + the contract ack). Two different contracts; folding one into the other would be a behaviour
change, not a de-duplication.

```python
#!/usr/bin/env python3
"""Prove each correction sub-diff COMMENT-ONLY under [[B254]], two independent readings.

  (A) PER-HUNK CLASSIFICATION — every `git diff -U0` hunk is COMMENT-ONLY (all +/- lines are comment or blank),
      TRAILING-COMMENT-ONLY (its comment-stripped text is an identical multiset), or CODE.
  (B) TOKEN-LEVEL EQUIVALENCE — the comment-stripped, whitespace-normalised token stream of each file is diffed.
      A comment edit is invisible here, so every surviving region must be nameable code.
Usage: b254_comment_only.py <base-ref> <path> [<path>...]
"""
import re, subprocess, sys, difflib

def strip_comments(t):
    out, i, n, s = [], 0, len(t), False
    while i < n:
        c = t[i]
        if not s and c == '/' and i+1 < n and t[i+1] == '/':
            while i < n and t[i] != '\n': i += 1
        elif not s and c == '/' and i+1 < n and t[i+1] == '*':
            i += 2
            while i+1 < n and not (t[i] == '*' and t[i+1] == '/'): i += 1
            i += 2
        elif c in '"\'':
            q = c; out.append(c); i += 1
            while i < n and t[i] != q:
                if t[i] == '\\': out.append(t[i]); i += 1
                if i < n: out.append(t[i]); i += 1
            if i < n: out.append(t[i]); i += 1
        else:
            out.append(c); i += 1
    return ''.join(out)

TOK = re.compile(r'"(?:[^"\\]|\\.)*"|\'(?:[^\'\\]|\\.)*\'|[A-Za-z_]\w*|\d+\.?\d*|[^\s]')
def tokens(t):
    return TOK.findall(strip_comments(t))

def is_comment_or_blank(line):
    s = line.strip()
    return (not s) or s.startswith('//') or s.startswith('/*') or s.startswith('*') or s.startswith('*/')

base = sys.argv[1]
for path in sys.argv[2:]:
    old = subprocess.run(['git', 'show', f'{base}:{path}'], capture_output=True, text=True).stdout
    new = open(path).read()
    d = subprocess.run(['git', 'diff', '-U0', base, '--', path], capture_output=True, text=True).stdout
    hunks, cur = [], None
    for ln in d.split('\n'):
        if ln.startswith('@@'):
            cur = [ln, []]; hunks.append(cur)
        elif cur is not None and (ln.startswith('+') or ln.startswith('-')) and not ln.startswith(('+++', '---')):
            cur[1].append(ln)
    comment_only = [h for h in hunks if all(is_comment_or_blank(l[1:]) for l in h[1])]
    rest = [h for h in hunks if h not in comment_only]
    def trailing_only(h):
        add = sorted(strip_comments(l[1:]).strip() for l in h[1] if l[0] == '+')
        rem = sorted(strip_comments(l[1:]).strip() for l in h[1] if l[0] == '-')
        return [x for x in add if x] == [x for x in rem if x]
    trailing = [h for h in rest if trailing_only(h)]
    code = [h for h in rest if h not in trailing]
    print(f'== {path}')
    print(f'   hunks: {len(hunks)}   COMMENT-ONLY: {len(comment_only)}   '
          f'TRAILING-COMMENT-ONLY: {len(trailing)}   CODE: {len(code)}')
    for h in trailing:
        print(f'     trailing-comment hunk {h[0].split("@@")[1].strip()} (code text identical before/after)')
    for h in code:
        print(f'     CODE HUNK {h[0].split("@@")[1].strip()}  (+{sum(1 for l in h[1] if l[0]=="+")}'
              f'/-{sum(1 for l in h[1] if l[0]=="-")})')
    ta, tb = tokens(old), tokens(new)
    sm = difflib.SequenceMatcher(None, ta, tb, autojunk=False)
    diffs = [(t, i1, i2, j1, j2) for t, i1, i2, j1, j2 in sm.get_opcodes() if t != 'equal']
    print(f'   TOKENS: {len(ta)} -> {len(tb)};  differing regions: {len(diffs)}')
    for t, i1, i2, j1, j2 in diffs:
        print(f'     {t:8s} -{i2-i1:4d} +{j2-j1:4d} tokens :: ' +
              (' '.join(tb[j1:min(j2, j1+14)]) if j2 > j1 else '') +
              (' | REMOVED: ' + ' '.join(ta[i1:min(i2, i1+14)]) if i2 > i1 else ''))
print('\nRULE: every B298 correction must appear ONLY in the comment-only classes and contribute ZERO token regions.')
```
