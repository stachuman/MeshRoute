### The source-shape model

The generator is **structural, not a token count**. Every recognised comparison site is attributed to its enclosing
**function**, its enclosing **preprocessor gate** and its enclosing **command-block chain**; then every scanned
function must be *classified*, and an unclassified one is a hard error. Five shapes are supported and all five are
exercised by fixture controls:

| | shape | where it lives |
| --- | --- | --- |
| S1 | `!strncmp(buf, "lit", N)` | `dispatch()` and most sub-verb dispatchers |
| S2 | `!strcmp(buf, "lit")` | `handle_cfg_set` keys, `handle_mobile`, `remote_encode` |
| S3 | `tok_eq(tok, "lit")` | `lib/console/console_parse.cpp` (`send` / `send_channel` / `send_layer`) |
| S4 | `preset_word_is(t, n, "lit")` | `src/firmware_ui_preset_verbs.h` (`ui preset …`) |
| S5 | `buf[0] == 'c'` beside an S1..S4 literal | the alias spellings `help`/`?` and `debug off`/`0` |

Three refinements were each **forced by a defect the first version produced**, and each is recorded at its site:

1. **Buffer separation.** `cfg set e2e_dm` tests its *key* once and its *value* twice; grouping every literal on the
   line published `cfg set e2e_dm (alias: on, true)`. The arm is now the literals compared against the **first
   buffer**; other-buffer literals are listed as argument-value comparisons instead of being dropped.
2. **Guard polarity.** `strcmp`/`strncmp` return **zero** on a match, so `!strncmp(…)` means *matches*, while
   `tok_eq`/`preset_word_is` return a bool, so `!tok_eq(…)` means *does not match*. Reading every `!` as a negation
   made `ble_dispatch_line`'s `if (… !strncmp(line, "peers ", 6)) return …;` look like a family guard and prefixed
   six later arms with `peers`.
3. **Min/end brace profile.** A net brace delta never closes a block on a `} else if (…) {` line, which published
   the sub-verbs `route add del` and `crashtest hang fault`.

### Both timer strategies, priced — ⛔ neither chosen

**⛔⛔ THE WHEEL HAS NO FREE ID, AND NO HYPOTHETICAL 92nd SLOT IS SPENT BELOW.** `lib/hal/timer_wheel.h:25` sets
`kCap = 91`; `lib/core/protocol_constants.h:403` states outright *"(kCap 91, all consumed)"*; `node.h:1528`'s
`kE2eAckDeadlineTimerId = 90` is the last one taken.

★★ **A finding worth the owner's attention: the "shared scan" option does NOT avoid the cap increase.** A shared
remote-admin expiry scan still needs *one* timer id, and there is no id to give it. What the two options actually
differ in is **how many** ids the increase must buy — one, or one per expiring record class.

**The wheel is priced by a mirror that is proved faithful, not assumed.** `TimerWheelStorageMirror<N>` reproduces
the wheel's storage (`bool _active[kCap]` + `uint64_t _due[kCap]`), and
`radmin 0e-B: the timer-wheel mirror is FAITHFUL` asserts the mirror at the real `kCap` equals
`sizeof(meshroute::TimerWheel)` and `alignof` exactly. The probe then measures all four on all three ABIs.

| | native | gateway | heltec_mobile | delta vs today |
| --- | ---: | ---: | ---: | ---: |
| `meshroute::TimerWheel` (the real type, `kCap` 91) | 824 / 8 | 824 / 8 | 824 / 8 | — |
| mirror at `kCap` 91 | **824 / 8** | **824 / 8** | **824 / 8** | ★ reproduces the real wheel exactly |
| mirror at 92 — **option 2**, one shared expiry scan | 832 / 8 | 832 / 8 | 832 / 8 | **+8 B** |
| mirror at 99 — **option 1** sketch, eight per-class ids | 896 / 8 | 896 / 8 | 896 / 8 | **+72 B (9 B/id)** |

**Option 1 — raise `TimerWheel::kCap`.**
· *Storage:* 9 B per id (1 B `_active` + 8 B `_due`), uniform on all three ABIs; the first id measures +8 because
alignment absorbs one byte, eight ids measure +72.
· *ABI/RAM:* the wheel is a single instance inside `device_hal`, so the cost is paid once per image, not per record.
· *Scheduler scan consequence:* `pop_due()` and `earliest_due()` are documented **O(kCap) per pump**
(`timer_wheel.h:33`, `:44`) and `earliest_due()` additionally bounds the idle sleep, so every added id lengthens
the per-loop scan and the wake-up computation. ⛔ 0e does **not** price that loop in microseconds — it has not been
measured on metal and an invented figure would be worse than none.

**Option 2 — one shared, re-armed remote-admin expiry scan.**
· *Precedent:* `node.h:1528` `kE2eAckDeadlineTimerId = 90` — *"single one-shot, re-armed to the earliest pending
-a send's deadline"* — and `node.h:1527` `kParkRefloodTimerId = 89`, the same idiom.
· *Timer storage:* one id ⇒ **+8 B** of wheel, plus whatever `Node` state the earliest-deadline bookkeeping needs
(⛔ not landed and therefore not measured).
· *Per-tick maximum row scan:* the union of every expiring candidate table. At the "modest" profile above that is
4 pending + 4 sessions + 2 assemblies + 2 retained + 8 ACK-debt + 16 seen + 4 transcripts + 2 ingress + 4 open
staging + 2 deferred = **48 rows** per fire.
· *Cadence:* one fire per earliest deadline rather than per tick, exactly as the two precedents behave.
· *Worst-case expiry lag:* zero by construction when the scan re-arms to the true earliest deadline; the lag
becomes non-zero only if the design coarsens the re-arm, which is the trade the owner would be ruling on.

⛔ **0e states both prices and recommends neither.** The owner rules exact capacities, the
authenticated/open/bootstrap resource partition and the timer strategy after QG PASS (R-RA-2 / R-RA-10).

## 5. 0e-D — the first concrete activation budget (R-RA-20)

### The two MAC window authorities, NAMED and reproduced exactly

**CTS wait — `Node::start_rts_timeout()`, `lib/core/node_mac.cpp:2356-2407`:**

```text
base  = airtime_routing_ms(unicast_rts_wire_len(crypted))      // 10 B plaintext / 11 B crypted (frame_codec.h:444)
      + airtime_routing_ms(terminal_cts_wire_len(crypted))     //  6 B plaintext /  7 B crypted (frame_codec.h:447)
shift = min(attempt, 2)          attempt = rts_max_retries - pending_tx->retries_left
delay = (base << shift) + 2*rx_window_slop_ms(routing_sf) + 1
```

⛔ It prices the **terminal** CTS, not the ordinary 3-byte one, because the sender cannot know whether the
receiver's completed-flight cache will hit — the file says so at its own site.

**ACK wait — `Node::start_ack_timeout()`, `lib/core/node_mac.cpp:2408-2429`:**

```text
base  = airtime_ms(chosen_data_sf, bw, cr, preamble, 18 + inner_len)
      + airtime_routing_ms(3)
      + rx_window_slop_ms(data_sf) + rx_window_slop_ms(routing_sf)
armed at base + 2
```

⛔ Its `18 + inner_len` length model is **the production authority's own** and is deliberately not replaced by
`data_frame_len` here: reproducing a timer means reproducing the number the timer uses. `data_frame_len` is what
0e-C asks for the frame that actually flies, and the two are reported side by side rather than silently reconciled.

### The maximum authenticated `TERMINAL{scheduled}` frame

§8.7 authenticated response envelope **26** + §8.9's one compact result code **1** + the bounded activation delay
**4** (its ceiling is 299 999 ms, which needs a u32) = **31 bytes of RPC body**. Through 0e-C's own framing
authority at the largest return-leg carrier overhead (**15**, cross-layer by key hash depth 4):
inner = 15 + 31 = **46 B**, frame = `data_frame_len(flags, type, 46)` = 8 + 1 + 46 + 4 = **59 B**.

### The measured budget at the ruled default PHY

PHY = the native build's own `-DLORA_SF=8 -DLORA_BW=125.0 -DLORA_CR=5` (`platformio.ini:59-61`),
`preamble_sym` 16. **`rx_window_slop_ms` = 0 on host and simulator** (the `IHal` default); the metal input is
**≈53 ms per radio turnaround** (`node_mac.cpp:2398`'s own note) and is named here as a *bench-measured input*,
⛔ not described as a compile constant.

the scheduled terminal has certainly left the first hop. ⓘ A stricter reading ("every attempt's window") would sum
to 167 + 333 + 665 = **1165 ms**, making the budget **7006 ms** and the default **14012 ms**. Both numbers are
given; ⛔ 0e does not choose between them — see §8.

### Controls — every input moves the result in the correct direction

Omitting **any** of the nine terms lowers the total (none is decorative). A slower SF, a narrower BW and a higher
CR each raise the airtime. A longer terminal raises its term. The CTS-wait grows with `attempt` and caps at
shift 2; a CRYPTED flight prices the wider 11 B/7 B identities. The ACK-wait grows with the DATA behind it.
