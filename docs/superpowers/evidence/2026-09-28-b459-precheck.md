## 3. Q3 — proposed completeness contract and identities

Use **expected declarations → terminal observations → one mandatory final comparison**, not success counters as the authority. The expected side must be built before dispatch and independently of which bodies execute. Every layer is a separate namespace. Require a nonempty expected set for each enabled layer, exactly one accepted terminal verdict per declared identity, no duplicate declaration/observation, unknown identity, missing result, extractor mismatch, malformed record or recorded guard failure. Wrong outcome kinds fail even when totals match.

| Layer | Suggested stable key and declaration source |
|---|---|
| Canvas | `canvas/v3/P1a`, `canvas/v4/P1a`, etc.; derive branch-appropriate declarations from the probe source with the actual build defines. **P4a runs ten times at :173**: use explicit iteration keys `P4a/0`…`P4a/9` (or a declared multiplicity expanded before execution), not ten duplicate verdicts for one ID. Do not infer the expected multiplicity from observed calls. |
| Trait | `trait/T1`…`trait/T14`, declaration from each call, separately verify extraction recognizes every call. |
| Missing trait | `missing/MR_UI_…`, from the full declared macro list; the execution iterator must not be the only source of expected items. |
| Structural | `struct/S1`, `struct/S2/mr_ui_init`, `struct/S3/<stable-property>`, `struct/S6/<macro>`, etc. Current human labels sometimes include measured counts; use stable IDs, keeping human text for diagnostics. Expand all three literal loops independently. |
| Wiring | `wiring/W49`, plus `wiring/W49/control/1`…`/6`; control expectations derived from that declaration's sed arguments. **Ordinals are adequate** within a stable check ID if the brief freezes the ordinal→substitution→property mapping. They need no wholesale renaming. A control reorder/removal is a ledger change, not just another count. |
| Canvas mutants | `negctl/v3/<C-id>`, `negctl/v4/<C-id>` from both original AST lists. Enumerate expectations before any execution filtering. Record the actual accepted outcome for each, including permitted compile failures. |

The baseline contains **592 terminal identities** after expanding P4a and namespacing arms: 124+110+14+12+23+60+186+60+3. This arithmetic is a review cross-check, **not** the new implementation's authority or a replacement for derived sets. In diagnostic `--no-neg`, 529 are enabled and the 63 canvas-mutant declarations are explicitly skipped by mode.

Both canvas binaries and negctl must expose executed IDs and outcomes. They need not print hundreds of new human lines: a machine-readable TSV/JSON result file or prefixed record stream is sufficient. Keep the old human summaries for readers. Positive canvas runs and each compiled mutant need separate run namespaces/files so their CHK records cannot satisfy each other's expectations. A negctl run must finish with a completed-results ledger, not `len(MUT)` masquerading as execution.

**Important limit of source-derived expectations:** removing a declaration and its call together changes the authority itself; neither B456 nor any same-source extractor can infer the deleted intent. Therefore two proofs are needed:

1. Runtime completeness against the current declared set, with an independent call-site/extractor agreement that fails on unsupported syntax, skipped branches and missing registrations.
2. Coverage preservation against the **frozen pre-change identity/property manifest**, allowing only declared instrumentation changes (e.g. P4a iteration IDs). Delete-a-CHK and shrink-the-loop regressions must exercise this boundary. A checked-in descriptor/manifest, independently reconciled to call sites, is reasonable if needed; do not write an extractor that simply shrinks both sides together and claim it catches removed declarations.

B456's current extractor supports its own strict call spelling. Copying its regex to arbitrary shell syntax would not provide that guarantee. W2's evidence parser is useful for an independent census, but executes shell argument expansion for trusted call text and is not a drop-in fail-closed production parser. Keep declaration syntax narrow and reject unrecognized/ambiguous calls.
