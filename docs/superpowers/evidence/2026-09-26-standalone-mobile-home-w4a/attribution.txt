**The "source UNCHANGED" rows, measured rather than assumed.** I compiled `src/firmware_ui.cpp.o` for `heltec_mobile` in
two scratch copies of the tree (outside the repo; `pio run -t <object>`, `MESHROUTE_GIT_REV_OVERRIDE=b206b206b206`):
one with the verified base sources (`base-copies/`), one with the final ones. The scratch final object's symbol table
equals the measured `.pio-measure/env/heltec_mobile/…/firmware_ui.cpp.o`'s exactly. In the OBJECT, base → final:
`ui_fmt_home_age` 181→180, `ui_team_age_bucket` 96→95, `on_outcome` 249→248, `settings_activate` 534→533,
`saved_keys_select_gesture` 128→129, `ui_route_recv_push$isra$0` 303→299. So the shifts are already present at compile
time, in functions whose source W4a does not touch (the model header's only code change is the formatter's addition).
The translation unit grew, and GCC's unit-wide optimizer and code generator emitted slightly different code for them. The
ELF keeps `firmware_ui.cpp.o`'s copy of these weak/local symbols. Six more weak functions shift inside the object
(`GuardedConsole::write` 30→33, `project_team` 330→326, `ui_prov_join_team` 421→417, `apply_team` 490→494,
`on_gesture` 519→523, `provision_gesture` 983→979), but the linker keeps another object's copy, so their ELF sizes are
unchanged. Object-vs-ELF sizes also differ (e.g. `settings_activate` 533 vs 521) because Xtensa link relaxation rewrites
code. `saved_keys_select_gesture` is the one where that gives a different sign (+1 object, −3 ELF).
