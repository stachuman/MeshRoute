`tools/gen_command_inventory.py` gained a projection over its **already classified** rows — it does not re-scan

| stage | rule | rows |

★ **Surface 3 is load-bearing, and the 42 → 49 distinction reproduces from source.** Projecting Surface 1 alone
gives **42** names on `full_oled`; the seven names `parse_command` owns — `peerkey`, `peername`, `reqpubkey`,
`resolve`, `send`, `send_channel`, `send_layer` — are consumed by the console token parser and **never reach
`dispatch()`**, so a Surface-1-only projection loses them silently. 42 + 7 = **49**.

Excluded, and why: `service_console` and `ble_dispatch_line` are callers that only re-test lines another surface
already owns (counting `service_console` would double-count `peerkey`); Surface 2 sub-verb dispatchers are not
primary; the `remote_encode`/`remote_exec` surfaces are `radio(REMOTE_CMD)`, not the serial dispatcher.

Canonicalization actually exercised on this tree: `cfg set` → `cfg` (rule 4); `help (alias: ?)` → `help` only, `?`
is punctuation and not a second command (rule 5); `join (alias: create)` → **both** `join` and `create` (rule 5,
word alias); `join`/`create`/`joinprofile` each carry a complementary `X` / `!(X)` row pair and are therefore
ungated (rule 7); the two `peers` rows and the repeated arms de-duplicate after gating (rule 7).

## 9. Console-sink runner self-pins ([[B294]]) and the sabotage

**Before:** `run.sh` printed `PINS …` and enforced **only** `unusable_controls`; every other term was checked
solely by the wrapper, so running the gate directly could print PASS after coverage shrank.

**After:** the pins live in `run.sh` with written arithmetic and are compared **before** PASS; the term that
differed is named and the runner exits nonzero.

| pin | value | derivation |
| --- | --- | --- |
| `PIN_PROFILES` | 6 | the six real board macro sets |
| `CHECKS_PER_PROFILE` | 120 | 52 §B95 sink rows + 68 §0g help rows (H0 1, H1 4, H2 6, H3 6, H4 6, H5 20, H6 8, H7 16, H8 1) |
| `PIN_CHECKS` | **720** | 120 × 6 — every profile runs the same rows now (a gated name changes the LIST, not the row count). 0a's 972 is retired with the per-topic rows that scaled it. |
| `PIN_STRUCTURAL` | 20 | `structural.py` S1..S20 |
| `PIN_BLE_GUARD` | 212 | 53 corpus lines × 4 assertions (B1..B4) |
| `PIN_CONTROLS` | **47** | 8 sink + 11 source + 23 help + 5 BLE; the 23 help = 13 rendered-index + 2 structural + 3 router + 5 oracle |

A missing, non-numeric, zero or differing count fails; an extra/missing profile fails twice (`profiles` and
`name_comparisons`). No environment variable or flag can raise or lower a pin in a normal run.

**Executed sabotage (`run.sh --pin-selftest`, exit 0):**

```
   ok   comparator observed='10' expected=10 -> ok
   ok   comparator observed='9'  expected=10 -> refused
   ok   comparator observed=''   expected=10 -> refused
   ok   comparator observed='abc' expected=10 -> refused
   ok   comparator observed='0'  expected=10 -> refused
   ok   dropped profile: 6 probe binaries STILL GREEN, runner refused (exit 1) on profiles+checks
SELFTEST OK — every pin class refuses
```

★ The last row is **exactly the F4 hole**: `MRPROBE_SELFTEST_DROP` removes one profile, every probe binary the
child launched still prints `0 failed`, the observed counts fall to `profiles=5 checks=600`, and the runner
refuses. The hook can only ever *reduce* coverage, so it cannot manufacture a PASS. The selftest never prints the
gate's PASS wording, and `--no-neg` remains `PROBE-ONLY` and prints neither `PASS:` nor a `PINS` line (verified:
`PROBE-ONLY` ×1, `^PASS:` ×0, `^PINS` ×0). The wrapper
`tools/test_probe_console_sink.py` keeps the same expected values as an independent second reader **and** pins
that the runner performs the judgment (`test_the_runner_enforces_its_own_pins`).
