### 1.1 `custody_row_matches_report(row, rec)` — §4.4's key, one line per term

```text
row.ctr_h        == rec.failed_ctr
row.return_kind  == node_id
row.return_peer  == rec.failed_dst
row.layer        == rec.reporter_layer
row.outward_type == rec.failed_type
row.target_kind == key_hash && (rec.notice_flags & HAS_DST_HASH)  ⇒  row.target == rec.dst_hash32
```

The hash term is a CROSS-CHECK: absent `HAS_DST_HASH` never refuses, and a **node-id row is never
hash-compared at all** (its `target` is a node id; comparing it to a 32-bit hash is a category error that
happens to be arithmetic — the `HashQuerySeen::by_id` key-space lesson).

### 1.2 The scan, and the four dispositions

`deleg_custody_lookup(rec, reporter_origin, out_action, out_matches)`:

1. **`deleg_ack_prune_expired(e, now)` is the FIRST statement of the loop**, exactly as `deleg_ack_reserve`,
   `deleg_ack_put` and `deleg_ack_translate` do;
2. only `state == active && custody_state == eligible` rows are counted (`live_eligible`) or matched;
3. the disposition is explicit, never a nullable row:

```text
no_live_rows = 0   zero live eligible rows after the prune  -> SILENT (the ruled normal case)
no_match     = 1   >=1 live eligible row, zero exact matches -> one bounded diagnostic
ambiguous    = 2   >1 exact match                            -> one bounded diagnostic, nothing sent
exact        = 3   exactly one                               -> the action is materialized
```

### 1.3 `DelegCustodyAction` — the bounded, stack-only action

| member | bytes | note |
| --- | --- | --- |
| `CustodyFailureRecord record` | 28 | the parsed record COPIED, `record_len` normalized to 24 **in the copy only** |
| `CustodyTranslatedTail tail` | 8 | `original_reporter` / `target_kind` / `mobile_ctr` / `target_value` |
| `uint32_t mobile_hash` | 4 | the `send_by_hash` destination |
| `uint32_t target`, `return_peer` | 8 | ---- the COMPLETE row identity, for the post-send recheck ---- |
| `uint16_t ctr_h`, `ctr_m` | 4 | |
| `uint8_t layer`, `outward_type`, `target_kind`, `return_kind` | 4 | |
| **total** | **56**, alignof **4**, no padding anywhere | pinned by `static_assert` in `node.h` (compiled by **every** board toolchain) and re-asserted in §B278-S3/20 |

⛔ It holds no `PostAck`, no `PendingTx`, no 241-byte buffer, no ring and no pointer into row storage. It is
never a `Node` member: `sizeof(Node)` is unmoved on all three ABIs (§10).

### 1.4 The commit — `deleg_custody_mark_forwarded(action)`

Predicate = `state == active && custody_state == eligible` **and every one of the nine identity fields**
(`mobile_hash, ctr_h, ctr_m, layer, outward_type, target, target_kind, return_peer, return_kind`).
It writes `forwarded` **iff `hits == 1`**; zero or several change nothing. ⛔ A slot number is never authority.
It writes ONE field — `state`, `ts_ms` and every identity field keep their values, so the later E2E ACK still
translates ctrH→ctrM and clears the row.

⛔ **No age test in the commit, deliberately**: the lookup pruned the ring at the same `_hal.now()` and the
loop task is single-threaded, so an age term would be a branch no fixture could reach. Stated in-source.

## 3. Construction of every prefix and tail field

| field | value | where from |
| --- | --- | --- |
| offsets 0, 3..23 | the parsed direct record, UNREINTERPRETED | `out_action.record = rec` |
| offset 1 `record_len` | **32**, stamped by the S2 packer | the copy is normalized to 24 first; the wire length of the original is untouched |
| offset 2 `notice_flags` | `\| 0x40`, stamped by the S2 packer | ⛔ no caller writes offsets 1, 2 or 24-31 |
| 24 `original_reporter` | `pa.origin` | the OUTER reporting relay |
| 25 `target_kind` | `row.target_kind` | mapped `DelegAckPeer -> CustodyTranslatedTargetKind` |
| 26 `mobile_ctr` | `row.ctr_m` | ctrM — what the mobile is waiting on |
| 28 `target_value` | `row.target` | the row's RETAINED mobile-visible target, ⛔ never inferred from `failed_dst` |

**The `record_len > 24` case, in full (§B278-S3/8).** The direct report arrives with `record_len = 28` and a
four-byte unknown tail. H1 stores **28 bytes** (§7.2's "including any accepted future tail") and pushes them;
the translation copies the 24-byte semantic prefix, sets the COPY's `record_len = 24`, and the S2 packer then
stamps 32. The unknown direct tail is **not** forwarded — §6.2 defines bytes 24-31 and nothing else may occupy
them. The aired 32 bytes are byte-identical to the no-tail case.

Each field has its own falsifier: `b251hash` S41 (normalization dropped), S42 (`original_reporter` becomes
`failed_origin`), S43 (`ctr_h` as `mobile_ctr`), S44 (`return_peer` as `target_value`), S45 (`target_kind`
hard-wired) — all RED.

**The stale action (§B278-S3/13), four arms.** ⛔ No production path can produce one: inside
`custody_failure_receive` nothing mutates the ring between the two calls (`reply_to_hash == 0` and

- (a) positive control — an action against a live row commits **once**, and a second commit answers false;

- (d) TWO rows share the action's complete identity ⇒ **NEITHER** is marked (this arm exists because the
