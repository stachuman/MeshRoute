## 0b-0 §3 — THE FAILURE BYTES, AND THE OPERATION ORDER

```cpp
static void do_regen() {
    mrnv::IdBlob idb{};
    mrnv::load_id(idb);                                          // 1. preserve the existing name (if any)
    mrrng::fill(idb.seed, sizeof idb.seed);                      // 2. a FRESH 32-B HW-RNG seed
    idb.magic = mrnv::kIdMagic; idb.version = mrnv::kIdVersion;  // 3. stamp the same magic/version
    if (!mrnv::save_id(idb)) { mrcon.println(F("> regen err nv_save_failed")); return; }   // 4. persist /mrid
    meshroute::identity_from_seed(g_identity, idb.seed);         // 5. derive
    g_node.set_identity(g_node.node_id(), g_identity.key_hash32);// 6. install the ROUTING identity
    g_node.set_crypto_identity(g_identity.x_secret, g_identity.ed_pub);  // 7. install the E2E crypto identity
    mrcon.print(F("> regen ok"));                                // 8. report
    print_identity(idb);
}
```

★ **Steps 5-7 are BELOW the `save_id` gate**: on a refused save the function `return`s at step 4, so **neither the
installed identity nor the crypto identity moves**. 0b preserves that order and that gate exactly — the only change
in this function is which `Print&` steps 4 and 8 write to.

`mrnv::save_id(b)` = `write_slot(kSlotId, &b, sizeof b)` (`src/device_nv.h:1035`); on the probe's `BOARD_HELTEC_V3`
arm that is `Preferences::begin(ns,false)` → `putBytes` → `n == len` (`device_nv.h:961-967`), i.e. the outcome is
decided by the Preferences medium and nothing else.

## §4 — 0b-2: THE WIRING GATE (`tools/probe_inbox_verbs/`)

**Why this probe and not a new one (U1):** it already compiles the REAL `src/firmware_commands.cpp` +
`src/firmware_inbox.cpp`, links the real `lib/core`/`lib/console`, defines the production device context, and
drives `mrfw::dispatch(line, len, Print&)` — the one router both transports use. No second `regen` parser and no
lookalike handler was created; the checks call `dispatch()`, never `do_regen` (which is `static` and unreachable
by design).

### What was added

* **`fakes/esp_random.h`** — the constant `0x5A5A5A5A` became a deterministic, replayable LCG stream plus a draw
  counter. It provides a FACT (the entropy source's bytes); the seed is still assembled by the real `mrrng::fill`,
  the identity still derived by the real `identity_from_seed`, the record still written by the real
  `mrnv::save_id`. ⓘ A constant cannot distinguish "production drew 32 fresh bytes" from "production wrote back
  the seed it loaded" — every draw would look alike. Nothing in the repo but `src/device_rng.h` calls
  `esp_random()`, so no other check can see this change.
* **`fakes/Preferences.h`** — a compile shim became a **store**: a 4-slot `(namespace, key) -> bytes` table with
  the medium's honest facts (`ns_present` / `rw_ok` / `fail_write`) and two `⛔ DISHONEST` switches that exist only
  to be mutated by C12/C13. ⛔ **The DEFAULT state is byte-for-byte the old behaviour** — `begin()` false on both
  modes, `isKey`/`getBytesLength`/`getBytes` 0/false, `remove`/`clear` true — so every pre-0b inbox-verb check
  reads an identical platform. **Measured: all 39 pre-existing W rows kept their previous verdicts** (71 − 32 = 39,
  0 failures), and controls C1..C7 still redden exactly the rows they reddened before.
  ⓘ It had to grow at all because the old fake made `mrnv::save_id` *always* fail: one of `regen`'s two arms was
  structurally unreachable and the byte-exact SUCCESS line could not be observed.
* **`probe_main.cpp`** — 32 new checks (R1..R32) driven through the real dispatcher, over the real `LineSink` and
  the real `mrcon`, with independently resettable capture sinks.
* **`run.sh`** — pins re-derived; the tree-integrity md5 widened to every touched production/probe/fake file
  (`firmware_commands.h`, `dispatch_sink.h`, `fakes/Preferences.h`, `fakes/esp_random.h`); `build_variant`'s
  ack-only include-shadow parameter generalised to a **shadow dir** (three headers now use it); the control
  verdict now NAMES its failing rows (the `probe_ble_line` idiom, U3).

### The independence of the expected bytes

The golden hash is **not** read back out of the global the command writes. The probe replays its own entropy
stream through production's `mrrng::fill` and derives the identity with production's `identity_from_seed`
*before* the drive, then rewinds the stream:

```cpp
static void expected_next_identity(uint8_t seed_out[32], meshroute::Identity& id_out) {
    rng_reset(); mrrng::fill(seed_out, 32); meshroute::identity_from_seed(id_out, seed_out); rng_reset();
}
```

⇒ a `regen` that skipped the draw, drew a different count, or persisted the seed it had loaded produces a byte
mismatch, not a coincidence. Separately, **R14 pins "exactly 8 UPPERCASE hex digits" by scanning the emitted text**
(`isxdigit` + a lowercase veto) rather than by reusing the `%08lX` that built the golden line — so the format
specifier and the assertion cannot agree with each other while both being wrong.
