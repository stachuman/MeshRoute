## The defect (from the row, condensed)
On a node whose persisted `sf_list` is EMPTY, `team new` is a dead-end with a self-contradictory diagnostic:
`ProvErr::incomplete_phy` (`src/firmware_config.cpp:1539-1542`) prints a remedy whose suggested command
(`team new freq=869.0 sf=7 bw=125`) fails the SAME check, and names `sf_list(DATA SF)` although `sf_list=` is
⛔ not a `team new` key ([[B211]]'s deliberate tail omission — freq/sf/bw ride the tail, the sf_list is
preserved from the persisted record). The only escape is `cfg set sf_list <…>`, which nothing states.

## Required (the ruling, verbatim in intent)
The `incomplete_phy` refusal **names WHICH part is missing**, and **when it is the persisted `sf_list`, the
remedy points at `cfg set sf_list 6,7`** — ⛔ never presented as an inline `team new` key. When the missing parts
are tail-settable (freq/sf/bw), the existing inline suggestion stays right. ⛔⛔ **Untouched:** the tail grammar,
[[B211]]'s omission, and every accept/refuse OUTCOME — the same inputs refuse exactly as before; only the text
(and, if you choose, the error's classification) moves.

## Shape guidance — decide, and say why
The console arm cannot say WHICH part is missing without being told. Two acceptable implementations:
- **(recommended)** split the service's `incomplete_phy` into a DISTINCT arm for "staged `sf_list` empty" (e.g.
  `incomplete_phy_sf_list`) — the classification then lives in the native-tested
  `firmware_provisioning_service.h`, `-Wswitch` sweeps every reader (the enum-arm-carries-its-reader-sweep rule),
  and the console maps each arm to its text. ⚠ An enum-arm addition is within the message-only ruling — it is
  wire-free and changes no outcome — but the sweep is mandatory and `prov_err_name` gains the arm.
- a console-side re-check of the persisted record before printing — keeps the enum but puts a decision in the
  TU no gate compiles; if chosen, the decision must still be extracted somewhere native-testable (the
  B212/B220/B223 lesson).
