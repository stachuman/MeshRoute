## 3. The sabotage control — which `[[maybe_unused]]` and why it is the right one

The register names "S1b's load-bearing `[[maybe_unused]]` on an MR_EMIT-only parameter":
`lib/core/node_hashlocate.cpp:2104` — `Node::deleg_ack_release(..., [[maybe_unused]] DelegAckReleaseCause cause)`,
whose comment (`:2098-2101`) states the precedent `enqueue_data(..., [[maybe_unused]] const char* tx_event, ...)`
in `node_mac.cpp`. `gateway` defines `MESHROUTE_NO_TELEMETRY` (idedata; `pio project config`), so removing the
attribute must add exactly ONE `-Wunused-parameter` to the gateway count and ZERO to every ESP32 env (they
suppress the class) — which is precisely the blindness being closed. The control must:
- mutate a COPY or restore byte-for-byte (md5 before/after; the sibling probes' idiom), never leave the tree dirty;
- prove the mutant COMPILED (object count unchanged, build rc 0) and the count moved by exactly +1 → RED;
- prove the six existing rows stay `ok` on the same mutant (the blindness, demonstrated rather than described);
- carry a vacuity check: if the `sed` matched nothing, the control is FAIL, not PASS.
A second control worth having: the [[B169]] LOCAL shape (`node_hashlocate.cpp:1638` `[[maybe_unused]] const bool
generic_lifecycle`) — already visible on `gateway_heltec` (the S1a evidence measured 174 vs 173) — as the
positive "the existing census does see this half" arm.
