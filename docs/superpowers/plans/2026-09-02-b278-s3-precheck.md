## 0. What S3 is, in one line

The first PRODUCER of the translated form: at a translating home, after G's five steps on a direct report, look
up the one ACTIVE `eligible` row by the wire-derived return key (spec §4.4), pack the 32-byte translated record,
originate it to the mobile's hash through `send_by_hash`, and mark the row `forwarded`. No consumer yet: every
receiver still refuses a translated record at the S2 interim guard until S4, so the corpus must stay 36/36 unless
S3's own telemetry moves a stream (§5 below).

## 2. The lookup (spec §4.4) against the S1b row

Row fields available (`node.h:2965-3000`): `mobile_hash, target, return_peer, ctr_h, ctr_m, layer, outward_type,
target_kind, return_kind, state, custody_state`. The match is:
`state == active && custody_state == eligible && ctr_h == rec.failed_ctr && return_kind == node_id && return_peer == rec.failed_dst && layer == rec.reporter_layer && outward_type == rec.failed_type`,
with the optional cross-check `target_kind == key_hash && HAS_DST_HASH ⇒ target == rec.dst_hash32`. Exactly one
match forwards; zero or more than one is a diagnostic only (spec §4.4). Add ONE ring method for it
(`node_hashlocate.cpp`, beside `deleg_ack_translate`); never scan the ring from `node_mac_rx.cpp`.
- `layer == rec.reporter_layer` is already implied by G's `layer_matches` (`reporter_layer == active_layer_id()`,
  the same value the row stored at reservation), so the term is a consistency check, not a filter.
- ACK-first: `deleg_ack_translate` clears the row (`:2043-2052`) ⇒ a later report finds no row ⇒ "no map" — spec
  §4.5's ruling falls out of the existing one-shot; no new state.
- Duplicate after `forwarded`: the lookup requires `eligible`, so a `forwarded` row is "no map" ⇒ no second send.
- Expiry: the one 300 s prune (`deleg_ack_prune_expired`, `:1921`) clears `forwarded` rows like any other; the
  `deleg_ack_expired` emit will now report `custody_state = 3` — ⚠ the S1b comparator C7 refuses `custody_state == 3`
  as "forwarded is unreachable" (`tools/compare_corpus_slice_s1b.py`) and the S1b census rejects it too. Both are
  S1b-era instruments; S3 must either retire that control with the correction idiom or keep them as historical
  and not run them as a gate. State it in the brief.

## 3. Packing the translated record — one trap

`pack_custody_failure_translated(in, tail, out)` takes the DIRECT-shaped record and REFUSES
`in.record_len != 24` (`lib/core/frame_codec.cpp:1326`). A parsed direct report carries the wire `record_len`
(24 today; >24 if a future reporter appends a tail). S3 must copy the parsed record and set `record_len = 24`
before packing (dropping the original's unknown tail is spec §6.1's "first 24 bytes" rule), or the brief must
rule that the packer treats the input length as informational. Tail: `original_reporter = pa.origin` (the
outer reporting relay), `target_kind = row.target_kind`, `mobile_ctr = row.ctr_m`, `target_value = row.target`.
The 32-byte buffer is a stack local; the bounded action must not copy `PostAck`/`PendingTx` (spec §7).

## 5. Corpus prediction

No corpus stream has a delegated flight that receives a custody report (S0 §3; unchanged by S1b/S2), so the
lookup can never match in the corpus and no translated record can air ⇒ 36/36 byte-identical on the seventh
table IF S3's new telemetry is silent on the "no live eligible row" path. S3 emits: `deleg_custody_forwarded{…}`
(never fires in corpus), `deleg_custody_forward_refused{…}` (never), and the §4.4 diagnostics. ⚠ Eleven direct
receipts exist in the corpus (s06 4, s07 1, s27 2, twin 4); an unconditional "no map" emit on every receipt
would MOVE four streams. Recommend: emit the no-map diagnostic only when the node holds ≥1 live `eligible` row
(bounded, and corpus-silent by construction); the ambiguity emit stays unconditional (unreachable). If the brief
chooses unconditional emits, it must plan a re-anchor proposal (eighth ruling) with per-line attribution.
