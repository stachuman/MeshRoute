## The slice
A standing probe (`tools/probe_board_abi.py` or the idiom-matched name — follow `probe_build_identity.py`'s
shape: bounded output, controls by default, exact-once anchors where source is pinned) that measures the
**board-ABI** `sizeof`/`alignof` of the pinned struct set — compile-only, no link, using the envs'
OWN pinned toolchains:
- **BOTH approved ABIs** (the two-env ruling's pair): xtensa (`heltec_mobile`'s toolchain) and ARM
  (`gateway`'s `toolchain-gccarmnoneeabi` — nRF52 builds only the non-OLED subset; probe the structs each
  ABI actually compiles, derived from the env's feature flags, ⛔ not a hand list of which-struct-where).
- **Mechanism** (the offered 6-line shape, hardened): a tiny probe TU per ABI declaring
  `char mr_abi_<Struct>[sizeof(<Struct>)];` (+ alignment mirrors) for each pinned struct, compiled `-c` with
  the env's real flag set (the same `-D`s the env passes — derive them, e.g. via `pio project config`/the
  build flags, so `MR_FEAT_*`/`MR_PROFILE_*` match the real TU's view), then symbol sizes read from the
  object (`nm`/`size`-class tools from the same package). ⛔ No link, no board build, seconds not minutes.
- **The pinned set** (extend deliberately, derivation written like `PIN_CASES`): the structs whose native
  `offsetof`/`sizeof` cases exist but are host-only — `UiState`, `UiSnapshot`, `UiModel`, `UiChrome`,
  `InviteWindow`, `InviteMember`, `InviteGrantResult`, `UiProvAnswer`, `UiProvIntent`, `ComposeSlot`,
  `ComposeList`, `UiPresetSlot`, `UiPresetBlob`, `PresetCatalog`, `SendReq` — plus any the sweep of the
  existing native resources cases surfaces. ⓘ ⛔ **CORRECTED 2026-08-28 (the coder's V1 catch — this brief's claim was WRONG):** this read
  "`sizeof(Node)` is ALREADY per-ABI pinned by its own static_assert compiled in board builds
  (`node.h:1968`)". `:1968`'s "per-ABI" note belongs to `ChannelReofferPending` (`:1982`); the Node assert
  sits at `:3528` INSIDE `#ifdef MESHROUTE_NATIVE` — host-only, its own ledger recording fourteen slices of
  hand-run per-ABI reveals. ⇒ `meshroute::Node` IS in the probe's pinned set (222008/117848/148616) — the
  standing form of that hand-run reveal. Genuinely covered elsewhere (unguarded asserts in every board
  build): the NV record structs + `ChannelReofferPending`.
- **Expected values PINNED per ABI** in the probe (the PIN_CASES discipline: updated deliberately with the
  old→new derivation written, prior entries kept visible). A silent board-only move ⇒ the probe FAILS.
- **Controls (each RED, non-vacuous):** a fixture struct engineered to diverge host-vs-board (the incident's
  shape: a pointer-adjacent u32 that lands in a host-only hole) proving the probe SEES divergence · a pinned
  value mutated · a struct removed from the probe TU while still pinned (coverage loss is loud) · the flag
  derivation broken (a feature-gated struct probed under the wrong flags must fail, not silently measure the
  stub). The B237 class: a compile failure of the probe TU is a FAILING verdict, never "measured".
- **Wiring as STANDING**: documented in the probe header as part of the resources discipline — any slice
  whose report claims struct costs runs it for the touched structs; the full pinned sweep runs at gates.
  Note the B206-manifest hook as future-optional (the B246 row's own suggestion), ⛔ not wired this slice.
