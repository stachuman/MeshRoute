## 0. What this is

Two instruments that future gates rely on are broken. This package repairs both and changes nothing else.

**Part A — the mutation harness, `tools/probe_ui_model_mutations.py`.**
- **B478.** `run_suite` captures the build and the native run with `text=True`, so strict UTF-8 decoding raises
  `UnicodeDecodeError` on a raw `0xBB` or `0xC5` from either stream before any verdict. In pre-check §2.1, 5 of 13
  real-child scenarios raise. The retained 64-KiB tail also drops a cut UTF-8 byte through `errors="ignore"`.
- **B490.** Once both doctest summaries parse, the native exit status is ignored. A failure summary followed by
  SIGSEGV returns `(1,1,1)`, which the worker credits as RED; a success summary followed by SIGSEGV returns `(0,1,1)`;
  a summary with exit 2 is accepted too (pre-check §2.1).
- **B490 is reachable by a real mutant, not only by a synthetic child.** Author V1 check of the pinned doctest
  (`.pio/libdeps/native/doctest/doctest/doctest.h`): on POSIX, `FatalConditionHandler::handleSignal` calls
  `reportFatal`, which runs every reporter's `test_run_end` — printing the summary — and then `raise(sig)`. A mutant
  that crashes inside a test case therefore prints a summary and dies by the signal. The review confirmed it by
  execution: a labelled one-case program that fails a `CHECK` and then raises SIGSEGV prints both summary lines and
  exits −11. No current battery entry is claimed to do this.

**Part B — the transcript comparator, `tools/probe_inbox_verbs/transcript.py` and `transcript_main.cpp`.**
- **B487.** The stock run fails at base: exit 2, `'mrble' has not been declared`. Its private build recipe lacks the
  real `device_ble.h`, the remote-action and client TUs and the two `--wrap` flags that `run.sh` uses. The driver
  prints three macros while the inventory's profiles have five. The CLI has no profile selector.
- **B488.** The generated `mr0c_serial_tail(const char* line, size_t pos)` gives the verbatim USB tail
  `sizeof(line) - 1 == 7`, where production's array gives 1,023. Every row longer than seven bytes is refused as
  `too_long`: 162 of 200 in the stock matrix, once the B487 gaps are patched in scratch.

**Owner rulings.** B478 is its own tool package, after W0 and before W7 (2026-09-29). B487 and B488 join it
(2026-09-30).

**B490 is covered here, inside B478's ruled contract.** B478's close-by condition requires preserved "verdict/exit
contracts", and the pre-check (§2.2, register B490) says the brief must name the exit-validation defect. This is an
author disposition, not a new owner ruling. The owner may overrule it at review (§6).

**Shape: one freeze, two independent parts on disjoint files.** There is no refactor increment. Replacing the
transcript's broken private recipe with the inbox runner's own builder is the B487 repair (C1: fix only). Revision 3
keeps the shape: B491 belongs to Part B, and B492's one-entry fix to Part A's file.

## 2. Contract

### 2.1 Part A — the mutation harness (B478, B490)

**A1 — Capture bytes.**
- Both `run_suite` subprocesses capture raw bytes: no `text=True`, no `encoding=` and no `errors=`.
- Nothing decodes the build's or the native run's output before classification.
- The build refusal keeps its meaning on bytes: a nonzero build exit, or `error:` in either raw stream, returns a
  build failure, and the native binary is never launched.
- The doctest markers are found in raw stdout by the same two patterns, as byte patterns, with the same first-match
  rule and group mapping.

**A2 — A verdict needs an agreeing exit (B490).** A verdict keeps its order and meaning: `(failed assertions, test
cases, assertions)`. It is returned only in two cases:

| Native exit | Summary | Result |
| --- | --- | --- |
| 0 | 0 failed test cases and 0 failed assertions | verdict — a clean tree, or a surviving mutant |
| 1 | ≥ 1 failed test case and ≥ 1 failed assertion | verdict — RED |

Both summaries must parse, and both are checked — not the assertion count alone. Everything else is a no-verdict
`run` failure:
- a signal (a negative exit), or any other exit status;
- exit 0 with any failure;
- exit 1 without a failed assertion;
- a missing or malformed summary.

The grounding is doctest itself: `cleanup_and_return` returns `EXIT_FAILURE` exactly when a test case failed, and
its POSIX fatal handler prints the summary before re-raising (§0).

**Recorded behaviour changes:**
- Exit 1 with a failed test case but no failed assertion used to be FAIL ("the suite still PASSES"). It becomes
  UNUSABLE. Both are non-RED, so a battery's exit status does not change.
- A clean baseline is accepted only in the table's first row. Any other clean run refuses the baseline with exit 2.
  A verdict with failed assertions (exit 1) keeps the existing "clean tree is RED" message. Every no-verdict clean
  run gets the "does not build / did not run" refusal, which now names the phase, the exit status and any signal.

**A3 — What a run carries.**
- A no-verdict result carries its reason (`build` or `run`), its exit status, and both raw streams separately and
  unmodified.
- A verdict result also carries both raw streams: the baseline's failing-output print needs them.
- The types are the coder's choice. The existing consumers keep their meaning.

**A4 — One human view of child bytes.** One escape function renders every human view of child output: the UNUSABLE
excerpts, the baseline refusal lines and the `.log` file.
- Bytes 0x20–0x7E other than `\`, plus tab and line feed, pass unchanged.
- `\` becomes `\\`.
- Every other byte becomes `\xHH`, with two lowercase hex digits.

The bounded view is the escape of the last 65,536 raw bytes of stdout followed by stderr. The bound applies to raw
bytes, so no byte is silently dropped at the cut. The view is for diagnosis only and is never evidence.

**Recorded diagnostic changes:**
- ASCII output without `\`, carriage returns or other control bytes renders byte-identically. The self-test's
  fabricated texts are unchanged.
- Valid non-ASCII UTF-8 renders as `\xHH` in the view; the raw files keep it intact.
- Excerpt lines split on line feeds only.

**A5 — Complete evidence reaches the parent.** Every UNUSABLE entry and every worker baseline refusal gets a retained
set under `.pio/mutation-unusable/<target>/`:
- the raw stdout and the raw stderr, as separate files, byte for byte;
- a metadata record: the target; the entry ID and label, or the worker for a baseline; the phase; the exit status
  and any signal; each stream's byte length and SHA-256;
- the bounded `.log` view at `unusable_log_path`, as today.

The existing `retained: <path>` line keeps its format and still names the `.log`. New lines may follow it.

**Transfer and ordering:**
- The raw bytes travel from the worker in its result file, in a lossless encoding, or in files beside that file in
  the scratch root.
- The parent recomputes each stream's length and SHA-256 and compares them with the worker's declared values. It
  then writes the set, re-reads it and verifies it.
- The parent does all of this before it exits, on every exit path after the merge — including the agreed abort
  codes 2–5 and the integrity code 9. That is always before `_cleanup_scratch` removes the worker trees.
- A mismatch or a failed write is a run-integrity failure, printed in the integrity block — never a silent loss. The
  existing exit precedence is unchanged: an abort every worker agreed on keeps its code; otherwise integrity exits 9.
- A failed write is handled, never an uncaught exception, and the parent carries on with the rest of the merge.

**When persistence itself fails,** the run does not claim retention. What remains is the console record: the entry
or worker, the phase, the exit status and signal, the declared and the recomputed length and SHA-256 of each stream,
the path that failed with its error, and the bounded view. The raw bytes are removed with the scratch root at exit,
as today. The integrity line says so and names `MR_MUT_KEEP_SCRATCH=1` for a rerun that keeps them. Cleanup does not
change (A8).

**A6 — Outer layers.** The rsync diagnostic and the parent's worker-output pump read bytes and decode them with a
total, visible policy (for example `backslashreplace`). Both stay fail-closed:
- an rsync failure still aborts with exit 9;
- the pump never raises, whatever the parent's locale, and never stops reading a worker's pipe.

Both are display only, never evidence.

**B7 — One validity contract, for runs and comparisons (review TPR-1).** A ledger is valid only against the
**expected matrix**: the ordered `(ID, command bytes, length)` rows that `derive_matrix` produces for the ledger's
declared, supported profile from the current inventory — derived without compiling. A ledger's own counts are
checked against that matrix and are never trusted in its place. A ledger is valid when all of these hold:
- **Head:** the first line is the tool's `# transcript` head, carrying `profile=` with a supported profile. Its
  provenance fields — label, `fw_main` path, source SHA-256 — are reported, not validated.
- **Identity line:** exactly one `MR0C-TRANSCRIPT v1 adapters=<shape>/<12 hex> lines=<N>` line, with `N` equal to the
  expected matrix size.
- **Profile line:** exactly one `MR0C-PROFILE` line, and it passes `verify_profile` for the declared profile.
- **Rows:** for each expected row, in order, exactly one `LINE` record whose ID, length and command bytes equal the
  expected row. The bracketed text is decoded by the driver's own escape rule (`\r`, `\n`, `\\`, `\xHH`) and compared
  byte for byte. No missing, extra, repeated or reordered row.
- **Records:** each `LINE` is followed by exactly one `SER` and one `BLE` record in the driver's full grammar. `SER`
  carries `usb`, `ble` and `fp`; `BLE` carries `ret`, `buf`, `nus`, `usb` and `fp`; `fp` carries every field of
  `print_fp`, in order. A missing or extra field is malformed.
- **End:** exactly one `MR0C-TRANSCRIPT END chk=<n> fail=<n>` line, and it is the last line. No other line appears.
- **Formats and conversions (B491):** a profile-line field that is not `name=value`, and a count longer than nine
  digits, are refused by name before any conversion. Only the validator's own refusal — and, for `--compare`, a
  file-read error — is caught. No broader handler turns a programming or build failure into a refusal or a
  comparison.

**The run path** validates the fresh ledger this way and also requires the child's exit 0. The ledger is the child's
stdout under the tool's head, which gains `profile=`. Stderr is captured separately and recorded; it is no longer
appended to the ledger. An invalid ledger is refused (exit 2), naming the first violation, and is never emitted as
valid.

**B8 — Comparison: `--compare A B`,** with no build.
- Both ledgers must be valid under B7 for the same declared profile. Otherwise exit 2, naming the first violation.
- Only validated records compare: `LINE` to `LINE`, `SER` to `SER`, `BLE` to `BLE`, never `SER` to `BLE`.
- Exit 0 when every record is identical. Exit 1 when any differs, naming every differing row ID and record.
- Provenance — the head fields and the adapters identity — is reported, not compared. A before-and-after run over
  two `fw_main.cpp` revisions against the same inventory therefore compares its rows.
- The expected matrix is always the current inventory's. A comparison against any other expected matrix would need an
  explicit input and contract, which this package does not add.
