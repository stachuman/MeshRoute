- **K1:** the `/mrteams` NV record — `TeamKeyBlob{magic, version, count, records[4]}` /
  `TeamKeyRecord{team_id u32, team_ch_pub[32], team_ch_priv[32], reserved[4]}` — following the **`/mrjoin`
  precedent end to end** (own kMagic/kVersion · the hoisted host-testable read sequence with the FOUR-state

  plus **boot restore**: install the key ONLY on an exact active-team match, deriving pub from priv on restore
  and rejecting corruption/mismatch.
- **K2:** the `/mrcfg` active-binding fact (active team_id + `team_key_active`) and the create/import/leave
  integration: normal reboot in-team ⇒ auto-restore · `team 0` clears the binding, RETAINS the record ·
  re-grant/re-key replaces that team's record atomically. ⚠ The `mrnv::kVersion` consequence is an **NV**
  version, ⛔ never `wire_version` — state it as the spec does.
- **The ruled policy, every clause a pin or mutation** (the spec maps them): `team_id==0` never stored · one
  record per team_id · identical material ⇒ ZERO flash writes (counted) · a FULL keyring FAILS LOUDLY, ⛔ never
  silently evicts a secret · no labels in the record · **temporary secret buffers WIPED** (the `apply_team` wipe
  discipline — follow it, cite it) · ⛔ knowledge of the public team_id NEVER silently reactivates a stored key.
