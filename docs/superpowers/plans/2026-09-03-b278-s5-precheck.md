## 5. Metal Part 54 — the source facts the bench text needs

### 5.1 The premise, verified against code (V1), and its ONE host gap

The whole arc assumes an intermediate static relay R generates a custody notice for the HOME's outward flight.
The generator's eligibility (`lib/core/node_cascade.cpp:277-322`) refuses `pt.mobile_src`
(`not_mobile_delegation`, `:279`). On the direct-hosted-transit arm the home does not re-originate: it FORWARDS
the mobile's DATA through `forward_item_from_post_ack` (`lib/core/node_mac_rx.cpp:56-66`), which never sets
`mobile_src` (TxItem default `false`, `lib/core/node_carriers.h:349`), and the RTS mark is copied from the item
(`lib/core/node_mac.cpp:1078`) ⇒ H1's onward RTS carries byte-5 b1 = 0 ⇒ at R `pt.mobile_src == false` ⇒ the
term passes; the other terms (plaintext, static plane, `addr_len 0`, not XL, not gw re-inject, reportable type)
are the ordinary Part 53 shape. The home RE-MINTS the counter for the forward (`admitted_ctr_h =
peek_next_ctr(d.dst)`, `node_mac_rx.cpp:1447`) ⇒ **ctrH ≠ ctrM in general**, and `origin` stays `home_id`
(stamped by the mobile, `node_mac.cpp:883`).
⚠ **No native case drives a REAL cascade at R on a REAL hosted forward.** §B278-S4/2 is end-to-end from a
SEEDED row plus a packed report; §CUSTODY-G/6 is static A→B→C. The premise above rests on code reading only.
⇒ I recommended a test-only host twin of Part 54 (M1 `send -a` → H1 forward + reservation → R terminal cascade
→ H1 correlation + translation → M1 accept). **RULED OUT by R-S5-3: straight to metal.** Recorded so the gap is
a decision, not an omission: if Part 54 fails at R for an eligibility reason, the host twin is the first
reproduction to build, on the `S4Chain` + `GPair` shapes in `test/test_custody_receive_g.cpp`.

### 5.2 Topology, roles and the run's validity criterion

`M1 (mobile) — H1 (its home, static) — R (static relay) — T (static target)`, H1→T only through R (Part 53's
RF arrangement with A=H1, B=R, C=T). Builds: M1 = a `MR_PROFILE_MOBILE` env (`platformio.ini:526-534`,
`heltec_mobile` / `heltec_v4_mobile`); H1/R/T static (a GATEWAY is never a mobile home — B132; `mobile status`
on M1 must read `REGISTERED home=<H1_ID>`). Validity (spec §15 closing sentence, Part 53 step 3): R's trace
must show `«rx DATA` from H1 then `»tx ACK` (the hop ACK = custody accepted) BEFORE its failed onward attempts
and terminal; trace format `lib/core/frame_trace.h:50-65` (` t=<ms> ms «rx <KIND> …` / `»tx <KIND> …`,
kinds BCN/RTS/CTS/DATA/ACK/NACK). A direct H1-origination failure (no R hop ACK) is not custody — invalid run.
