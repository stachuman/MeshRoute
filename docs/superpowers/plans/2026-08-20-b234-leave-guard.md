## The ruling (from the row, condensed — the row wins on any divergence)
**Every operation whose committed candidate changes `current_team_id != 0` to a DIFFERENT id or to ZERO requires
explicit confirmation, on EVERY transport.** Guarded: `team new`, `team <different-id>`, `team 0`, `leave`.
`factory_reset confirm` already satisfies the shape. ⛔ NOT gated: same-team re-key/PHY/no-change; any operation on
a teamless node (`current_team_id == 0` — nothing is being left).
★ The predicate is DELIBERATELY stronger than `rt_team_count() > 0`: the route table is transient and its
emptiness cannot prove the mobile is alone — ⛔ the predicate must not consult it, and tests must prove route
expiry cannot remove the guard.

## As-built anchors (verified 2026-08-20)
- All three `team` forms flow through `stage_team_candidate`/`apply_team` (`src/firmware_provisioning_service.h`)
  — the natural home for the shared predicate, BEFORE entropy, NV write, live apply or airtime.
- ⚠ **`handle_leave` (`src/firmware_config.cpp`) BYPASSES the service and wipes the whole NV blob

## Required shape (the row, verbatim in intent)
1. **ONE shared predicate** ("does this committed candidate leave/replace a non-zero team?") — pure,
   native-tested, consulted before entropy/NV/live/airtime on every transport.
2. **The typed request carries explicit confirmation** (a field on `TeamRequest`; the `leave` path's equivalent).
3. **Console/BLE: a stateless TERMINAL `confirm` token** (the `factory_reset confirm` / `joinprofile reset
   confirm` precedent). First unconfirmed attempt **refuses loudly and changes nothing** — a new `ProvErr` arm
   (⚠ panel-sized: `prov_err_name` renders verbatim on the OLED result row, ≤15 columns — the B230 lesson; the
   enum arm carries its mandatory `-Wswitch` reader sweep and the all-enumerators census case extends).
4. ⛔⛔ **The refusal NEVER echoes the command** — a `team <id> tkpriv=… ` line carries PRIVATE KEY MATERIAL; the
   remedy says "append ` confirm`" (or equivalent) without reproducing the input.
5. OLED: the adapter passes the flag after `create_confirm`; the on-glass flow is UNCHANGED for the operator.

## Pins
1. Each guarded verb × unconfirmed ⇒ loud refusal, ZERO writes / live calls / airtime (counted), on the console
   AND through the adapter path where reachable.
2. Each guarded verb × ` confirm` ⇒ proceeds exactly as today (outcome parity with the pre-guard behaviour,
   asserted against captured results).
3. Negative controls, each named: same-team re-key · same-team PHY-only · no-change · teamless `team new` —
   ⛔ none gated, no confirm demanded.
4. **Route-expiry cannot remove the guard:** the alone/no-route state still refuses unconfirmed (the predicate
   provably does not read the route table — a mutation making it consult `rt_team_count` goes RED).

   carries NO key bytes).
