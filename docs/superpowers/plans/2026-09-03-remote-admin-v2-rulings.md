## R-RA-5 — request-ID width

**Owner:** *"5. Yes - airtime is the most scare resource - can we shorten it even more? Only if you believe so."*
**Quality Agent's answer (given, and the owner did not overrule it):** keep a cryptographically random **64-bit**
`request_id`. A per-session counter is unsafe because bootstrap is read-only and returns the CURRENT epoch
(design §7.2), so a controller reboot would restart the counter under the SAME session key — XChaCha20 nonce
reuse. 48-bit random needs a hard per-epoch request cap (≈4 096) to reach p≈2^-25 and saves two bytes each way;
32-bit is unacceptable (p≈0.5 at 65 536 requests per epoch).
**Settled:** *random 64-bit `request_id`; no shorter width, no rebooting counter, no per-epoch cap.* The draft's
§9 sentence "A random 64-bit ID remains the compact proposal, not yet a frozen claim" becomes frozen; Slice 2
still pins the maximum requests per epoch and states the resulting bound (≈2^-33 at 2^16) in its evidence.

### R-RA-12 — a home is ONLY ever a static node (review A1)

**Owner:** *"Home node can be ONLY a static node. If that is not clear from source - make it clear there."*
**Settled:** a mobile's home is a static node (and never a gateway — [[B132]] stands). The design states it as an
invariant, and the SOURCE makes it explicit: the three delegation arms of `send_by_hash` that today hard-code
`/*plane=*/Plane::AUTO` toward `home_id` (`lib/core/node_hashlocate.cpp:1771-1788`) must stamp `Plane::GLOBAL`
(the wrapper to a static home is global by definition), so `flight_is_team_plane(AUTO, home_id)` can never resolve
a home id to the team plane through the `_team_peer` id bitmap (`lib/core/node_routing.cpp:823`, a mixed-id
collision shape). This is a `lib/core` change (s18-governed; corpus attribution owed) and belongs to its own
preparatory slice or the first carrier slice — the brief decides, C1 applies.

### R-RA-13 — `SOURCE_HASH` is MANDATORY on every RPC carrier (review A2)

**Owner:** *"Source hash MUST be attached - it is crypted anyway."*
**Settled:** every v2 request and response carrier attaches `SOURCE_HASH` (the `app_dm=true` path —
`send_by_hash`/`do_send`, `lib/core/node_mac.cpp:505`, `:200-207`); the legacy `send_remote_cmd`/`send_remote_response`
helpers (`node_mac.cpp:805-813`, `app_dm=false`, no hash) are not the carrier and are deleted with the legacy
mechanism. ⓘ Precision the design should keep: `SOURCE_HASH` rides in the CLEAR inner and is bound as AEAD
associated data (§8.1); the RPC body around it is what is encrypted. Its presence is a routing/return-identity
fact, not a confidentiality cost.

### R-RA-14 — ONE universal command-byte cap; the legacy truncation is a defect, not evidence (review A3)

**Owner:** *"If existing legacy sealed path truncates - it has to either use one common universal - which is correct
or create universal."*
**Settled:** confirms R-RA-7 as the only authority: one shared validator and one named `common_command_max_bytes`
for USB, BLE and remote. The legacy 56/63-byte silent truncation (`pt[64]`/`v[64]` at
`src/firmware_remote.cpp:92`; the `vl` truncation at `:190`) is
neither preserved nor used as the "existing command corpus"; it disappears with the legacy path (Slice 9), and no

### R-RA-15 — the E2E ACK on an RPC request is OPTIONAL, per request, default OFF (review B4 / D1)

**Owner:** *"e2e ack should be OPTIONAL - no command enforce it, only option (-e)"*
**Settled:** no RPC request requests the end-to-end ACK by default; the operator selects it per request with an
option. Consequences the design must state: (a) without the ACK there is no delegated-correlation row (R1=A) and
therefore NO [[B278]] custody feedback for that request — the RPC response is the receipt; (b) with the option the
request costs one extra return flight and one of the mobile's 8 correlation rows (`kDelegAckCap`, 300 s); (c) §14.1
bullet 1 ("requests the existing E2E ACK") becomes conditional on the option.
⚠ **Option letter — QA flag for the Author (R-RA-11 "keep it consistent"):** the owner wrote `-e`, but on the
existing console `-a` = request ACK and `-e` = encrypt (`src/firmware_commands.cpp:998`, `:1127-1128`). The `remote`
wrapper must reuse `-a` for the ACK option; `-e` must not acquire a second meaning. The owner is asked to confirm
`-a` (default reading: the owner meant "the ack option", not the letter).
**Author application, 2026-09-04:** no override was given; round 2 therefore freezes `-a` as the optional
E2E-ACK spelling and leaves `-e` with its existing encryption meaning.

### R-RA-16 — the activation delay: derived worst-case DEFAULT, runtime-CONFIGURABLE within bounds (review C2 / D2)

**Owner:** *"yes, we will accept worst but I'd propose to make it configurable so user can tune"*
**Settled:** `remote_action_activation_delay_ms` defaults to a DERIVED worst-case value (the delegated carrier's
worst-case response path with margin — the design writes the formula and its inputs, no bare literal) and is a
target-side `cfg` tunable with a named minimum and maximum (a floor so the action cannot fire before the
`scheduled` terminal has left the reply path; a ceiling below the 300 s outer bound). Adding the cfg key is an NV
field (own attribution, C4 idiom). The 300 s outer bound (`e2e_ack_deadline_xl_ms`) is unchanged.

### R-RA-17 — exclusivity confirmed: a node is EITHER managed OR managing (review C4 / D3)

**Owner:** *"That's the idea - either node can be managed or is managing."*
**Settled:** every board profile is exactly one of `{client=1, accept=0}` (mobile) or `{client=0, accept=1}`
(static, gateway); a profile enabling both or neither fails the build. **QA reading for the HOST build, stated for
the owner's veto:** the native test binary is not a product configuration; it must compile BOTH roles so one test
process can drive a controller and a target end to end (the same idiom that drives a home and a mobile in one
binary today). The exclusivity `static_assert` is therefore scoped to board profiles (`MR_PROFILE_*`); native
compiles `{1,1}` with every accept-side and client-side seam individually testable. If the owner wants the host
build exclusive as well, end-to-end host tests need two binaries and the design must say how they talk.
**Author application, 2026-09-04:** no veto was given; round 2 scopes exclusivity to board profiles and uses
native `{client=1,accept=1}` with separate role-disable controls.

### R-RA-15 addendum (owner, 2026-09-04) — the option letters, settled

**Owner:** *"remote command without '-a' will not require e2e ack, while remote command enforce encryption."*
**Settled:** on the `remote` wrapper `-a` is the only option in this family: present ⇒ the carrier requests the
end-to-end ACK (`DATA_FLAG_E2E_ACK_REQ`, a correlation row, custody feedback); absent ⇒ no ACK requested. There is
no `-e` on `remote`: an authenticated request is ALWAYS sealed by the RPC layer (§8), and the explicit `open` form is
cleartext by ruling 4 — the wrapper refuses `-e` rather than give it a second meaning. Source of the letters:
`-a`=ack, `-e`=encrypt (`lib/console/console_parse.cpp:93`, `src/fw_main.cpp:1400-1401`); `cfg e2e_dm` is the
encryption default, not an ACK setting.

### R-RA-20 — the activation delay: first-hop budget, named constants, 2× default (review H3)

**Owner:** *"agree - we go with 2x."*
**Settled:** `remote_scheduled_reply_path_budget_ms(cfg)` = the time for the `scheduled` TERMINAL to clear the
target's FIRST hop with the MAC's own retries (once the first relay hop-ACKs it, a target reboot no longer loses the
answer; delivery to the controller is the 300 s outer bound's job):

```text
budget(cfg) = airtime(RTS + CTS + terminal DATA + ACK at cfg PHY)      (lib/core/airtime.h airtime_ms)
            + cts_to_data_gap_ms                                      (protocol_constants.h:133, 5 ms)
            + rts_max_retries * rts_busy_retry_ms                      (:135 × :134 = 2 × 30 ms)
            + the MAC's CTS-wait and ACK-wait windows                  (named by Slice 0e from the MAC timers)
            + cascade_requeue_base_ms                                  (:273, 5000 ms — ONE requeue at the FIRST price;
                                                                        ⛔ not cascade_requeue_backoff_cap_ms 30 s, which prices
                                                                        later requeues; ⛔ not send_defer_ttl_ms, the no-route ring)
floor   = budget(cfg)
default = 2 * budget(cfg)                                              (the 2× is the owner's word, 2026-09-04)
ceiling = e2e_ack_deadline_xl_ms - 1                                   (:780, 299 999 ms)
```
Rough magnitude at SF8/125 kHz: budget ≈ 7-8 s ⇒ default ≈ 15 s. ⛔ The design states the FORMULA; the number is
published by Slice 0e's characterization; the "≈30 s" example is deleted. `cfg.remote_action_activation_ms` stays
runtime-configurable within [floor, ceiling] (R-RA-16, Slice 7a).

### R-RA-21 — command authority policy and generated-table gate

**Settled policy:** the generated command/subcommand inventory receives one minimum authority per semantic row:

- **open:** only exact, argument-free `status` and `routes`;
- **operator:** target-applicable ordinary diagnostics, configuration, network create/join/leave/switch,
  routing/gateway/radio operations, and operational reboot/prep-restart, subject to §13 scheduling;
- **owner:** target identity/security/ACL/key material, destructive inbox/storage operations, factory reset,
  fault injection and OTA; and
- **physical:** first-owner/recovery/root-identity operations on a managed target and management-private-seed
  generate/import/export/replace/remove on a controller. These remain local USB-only in v2.

Controller-only wrappers and trust-store commands do not become recursively target-dispatchable merely because
they occur in the generated inventory. Anything genuinely ambiguous or absent from the classified table refuses
closed.

**QA confirmation:** the current 177-row 0e rendering is not yet the ratified policy table: it renders two
different `peers` parser decisions as indistinguishable duplicate rows in both `dispatch` and
`ble_dispatch_line`. Before classification lands, the generator must either merge true duplicates or expose the
semantic discriminator. QA then requires every target-applicable semantic command/subcommand exactly once,
exactly one authority on every such row, no unclassified/multiply-classified row, and mutation controls for a
missing row, a duplicate semantic row, and an unclassified row.

### R-RA-22 — exact bounded-state capacities and one shared expiry timer

**Settled controller/mobile profile:** 4 `PendingRequestInline`, 4 `SessionCacheEntry`, 2
`ResponseAssemblyHeader`, 8 `ResponseChunk`, 2 `RetainedResultHeader`, and 8 `AckDebtEntry` rows: **4,272 bytes**
from the 0e candidate layouts. Inline sealed bytes are chosen; there is no separate `SealedRequestSlot` pool.

**Settled managed static/gateway profile:** 16 `SeenRequestRecord`, 4 `TranscriptHeader`, 8 `TranscriptChunk`,
2 `IngressOperationHeader`, 2 `IngressBodySlot`, 4 `OpenStagingSlot`, and 2 `DeferredActionRecord` rows:
**2,968 bytes** from the 0e candidate layouts.

The two authenticated ingress rows are partitioned so at least one is always available to owner/control work;
the four open/bootstrap staging rows have a peer-local maximum of one open response. Open/bootstrap work cannot
borrow authenticated transcript/ingress capacity, and authenticated ordinary work cannot consume the reserved
owner/control admission.

Expiry uses **one shared earliest-deadline scan**. `TimerWheel::kCap` grows once, 91 → 92, measured as +8 bytes
on host, ARM and Xtensa in the 0e mirror; no class receives a private timer ID. The scan visits only the bounded
rows resident in that product profile and re-arms to the true earliest deadline.

**QA confirmation:** the implementation pins every configured row count, proves both partition-starvation
directions, measures the production RAM delta independently on `gateway` and `heltec_mobile`, proves the inline
ownership/lifetime rules, and verifies one timer ID, `kCap == 92`, earliest-deadline re-arm, expiry at the exact
edge, and no per-class timer IDs. Candidate-layout totals are the ruling input, not permission for an unexplained
larger production delta.

### R-RA-23 — activation budget sums every CTS-wait attempt

**Settled:** the CTS-wait term in `remote_scheduled_reply_path_budget_ms(cfg)` is the sum of the wait windows for
attempts 0, 1 and 2, not merely the largest final-attempt window. At the characterized host/default PHY with zero
slop this changes the reference floor/default from the withdrawn 6,506/13,012 ms interpretation to
**7,006/14,012 ms**. Production remains derived from the configured PHY and includes the configured RX-window
slop in every timer term; the reference numbers are not literals.

**QA confirmation:** independent term-by-term recomputation must reproduce 7,006/14,012 ms for the characterized
zero-slop case; mutating away any one attempt window, counting only attempt 2, omitting a slop occurrence, or
hard-coding the reference value is RED. The floor remains one budget, the default exactly twice it, and the
ceiling 299,999 ms; an impossible configured interval refuses rather than clamps.

### R-RA-24 — 159-byte universal command TAIL and full BLE usability

**Settled:** `common_command_max_bytes = 159`, counted over the exact command line passed to the common command
dispatcher. It excludes the local `remote <target> ... -- ` wrapper and excludes the terminating NUL. The bound
is the current minimum of USB (1,023 accepted payload bytes), BLE (159 accepted whole-line bytes), and the
smallest authenticated v2 carrier's 201-byte command capacity.

The current BLE buffer therefore cannot expose the full remote allowance: the wrapper consumes some of its 159
bytes. The completed implementation must preserve all 159 command-tail bytes over BLE by deriving the maximum
legal remote-wrapper length (maximum target selector plus `-e`, `using=keyN`, optional `-a`, separators and
`--`) and satisfying:

```text
ble_remote_ingress_capacity_bytes
    >= remote_wrapper_max_bytes + common_command_max_bytes + 1  // terminating NUL
```

The same textual grammar is retained; no BLE-only RPC language is invented. If the measured static-RAM cost of
that derived buffer is unacceptable, the slice STOPS for a new owner ruling instead of shortening the command,
truncating it, or silently accepting a smaller BLE limit.

### R-RA-36 (owner, 2026-09-09) — B379 admission-response domain and separate codec preparation

**Owner, confirmed directly to QA/Author:**

> B379: the proposed admission-response format and separate codec preparation are approved.

Approval consumes the same revision-2 brief and coder receipt named in R-RA-35.

**Settled wire contract:** allocate REMOTE_RESP opcode **`0x5 ADMISSION_RESULT`**, actual ACL slot **0..9**
only. The exact 28-byte body is `[ctl 1][request_id LE64 8][request_ctl 1][admission_code 1][detail 1][tag 16]`.
It is authenticated with **K_session**, intentionally clear, fixed length, and has no ciphertext, response
sequence, epoch or open/sentinel form. `request_ctl` contains AUTH_EXECUTE, SAFE_ROLLOVER or FORCE_ROLLOVER
and the same ACL slot as the response. The result namespace is:

| Code | Meaning | Allowed request | Detail |
| --- | --- | --- | --- |
| `0x00` | `session_full` | AUTH_EXECUTE | Zero |
| `0x01` | `ingress_full` | AUTH_EXECUTE / SAFE_ROLLOVER / FORCE_ROLLOVER | Zero |
| `0x02` | `session_busy` | SAFE_ROLLOVER | Positive byte count; target consumer enforces its ruled transcript capacity |
| `0x03` | `executing` | SAFE_ROLLOVER / FORCE_ROLLOVER | Zero |
| `0x04` | `preparation_failed` | SAFE_ROLLOVER / FORCE_ROLLOVER | Zero |

For this new domain only, append **`request_ctl`, `admission_code`, `detail`**, in that order, after
`source_hash_le32` in the existing nonce preimage. Its no-sequence term is zero. The complete clear header
and stable logical controller SOURCE_HASH are AAD. All varying notice fields therefore affect both nonce
and authentication; an identical notice repeats byte-for-byte. Retain the current KDF labels and old-domain
preimages. The new decoder publishes a typed admission result only after successful authentication and
semantic validation. Reject reserved codes, unsupported request opcodes, mismatched slots, zero busy count,
nonzero unused detail, extra/missing bytes and bad authentication.

**Explicit supersession:** non-executed `session_full` and mutable `session_busy` replies use this domain,
replacing design §8.9's assignment to TERMINAL. Terminal codes `0x06/0x07` stay recognized for the frozen
codec vectors; no existing OUTPUT/TERMINAL/PROTOCOL_ERROR/bootstrap/rollover bytes change. An acknowledged
execute retry still uses the existing distinct authenticated `PROTOCOL_ERROR{already_acknowledged}`.

no new target producer, controller consumer, session/open behavior or Node allocation. QA then reissues the
7b-2 behavior brief at the actual committed successor. No global `wire_version` bump or corpus re-anchor is
