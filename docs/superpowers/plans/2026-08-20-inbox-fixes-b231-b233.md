## Fix 1 — [[B231]]: the INBOX list renders NEWEST AT THE TOP (owner-ruled)
As built, `InboxRowBudget::publish` (`src/firmware_ui_model.h:823-829`) copies each ring in stored order = pull's
oldest-first, so the newest message sits at the BOTTOM of its block. The retention (newest-wins eviction) is
already correct.
- **Fix: publish each ring in REVERSE.** The eviction shift and the one-conversion-path (U2) stay as they are.
- ⛔ **SCOPE BOUNDARY:** the BLOCK order (all DM rows, then all channel rows, never chronologically interleaved)
  is a documented spec §6.1 decision (no shared clock between the two seq spaces) — newest-first WITHIN each block
  needs no such rule; ⛔ do not touch the block order or attempt interleaving.

## Fix 2 — [[B233]]: a serviced DELETE refreshes the list (tick-ordering defect)

frame then freezes the PRE-ERASE snapshot AND consumes `dirty` ⇒ the stale row persists INDEFINITELY; a `double`
on it opens the NEIGHBOUR (identity tracking is correct, the pixels are stale).
