## The defect — ⛔ A DAMAGED-BUT-MOUNTABLE `/mrjoin` STILL ANNOUNCES `NO PROFILES`

`fs_read_slot` (`src/device_nv.h:364`) maps **every** `fs.open(path) == false` to `kSlotAbsent` with no `io` fact:

```cpp
if (!fs.open(path)) return kSlotAbsent;   // absent slot (first boot) — ⛔ not an error
```

That comment is **false against the vendored backend**. `File::_open`
(`~/.platformio/packages/framework-arduinoadafruitnrf52/libraries/Adafruit_LittleFS/src/Adafruit_LittleFS_File.cpp:121-153`)
does a **`lfs_stat` FIRST** and returns `false` for FOUR distinct facts:
1. `lfs_stat` rc is neither `LFS_ERR_OK` nor `LFS_ERR_NOENT` — a **metadata error**;
2. `LFS_ERR_NOENT` in read mode — the only genuine **absent**;
3. `rtos_malloc` failure in `_open_file` — an **allocation failure**;
4. `lfs_file_open` failure — an **open failure on a file that EXISTS**.

Only (2) is a fresh device. (1), (3), (4) are the store refusing to answer — the exact fact `JoinRead::io_failed`
exists to carry — and today all three read as `NO PROFILES`. The mount-failure fix closed only the fifth case.

⚠ **The test at `test/test_device_nv.cpp:569` ("an OPEN failure is an ORDINARY absent slot") ENCODES the false
claim.** It must be REWRITTEN to the tri-state below, ⛔ not kept alongside the fix.

## Verified library facts you may build on (all checked 2026-08-19 against the vendored source)

- `Adafruit_LittleFS::_getFS()`, `_lockFS()`, `_unlockFS()` are **public** (`Adafruit_LittleFS.h:78-80`) — marked
  "internal usage only" but callable; ⛔ no vendored file is edited (the vendoring rule).
- `Adafruit_LittleFS::exists()` (`Adafruit_LittleFS.cpp:137-146`) is the exact locked-`lfs_stat` idiom — but it
  **collapses the rc to a bool**, so it cannot be used as the lookup: the raw rc is the fact that matters.
- `LFS_ERR_NOENT` is available in the nRF arm via `littlefs/lfs.h` (already included through `Adafruit_LittleFS.h`).

## Required correction (the QG's five points, verbatim in intent)

1. **A tri-state nRF lookup/open result: `present` / `absent` / `io_failed`.**
2. **Use the underlying LittleFS result so ONLY `LFS_ERR_NOENT` means absent.** The adapter must surface the raw
   `lfs_stat` rc (a locked stat mirroring `exists()`); classification stays host-drivable.
3. **If the lookup says present but `File::open()` then fails → `io_failed`** (allocation failure, `lfs_file_open`
   failure — case 3/4 above). ⛔ Never `absent`.
4. **Preserve the existing call sequence for the other four records when `io == nullptr`** — no lookup call, no
   `size()` call, the identical `mount → open → read → close` they issued before, same `int` on every path. This is
   the same gate the `SlotIo` correction already pinned; extend that pin to the new lookup (a counted discriminator:
   `lookups == 0`).
5. **Controlled cases** (in `test/test_device_nv.cpp`, driving the REAL hoisted sequence against the fake):
   - NOENT → `absent`;
   - lookup/metadata error → `io_failed`;
   - present followed by open failure → `io_failed`.
