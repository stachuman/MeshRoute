## 4. Persistence mapping (spec §8.3) — verify against the store's key

`record_custody_failure(reporter, failed_ctr, layer, bytes, len, now)` writes `origin = reporter`, `msg_id =
failed_ctr`, `type = 0x81` (`inbox.h:201-221`). For a translated record S4 passes `tail.original_reporter` and
`tail.mobile_ctr`. The DM-store dedup/identity for outcome records is `(origin, msg_id)`; an E2E ACK receipt for
the same operation is stored `origin = the acker, msg_id = ctrM` — the two records never collide (different
origins) but a consumer matching by `(origin, msg_id)` alone would not pair them; spec §8.4's rule is the full
tuple. State it in the brief so the "generic exact-tuple consumer fixture" (§12-S4 item 5) matches on
`{failed_origin, reporter_layer, target_kind, target_value, mobile_ctr, failed_type}` from the body, never the
record key.
